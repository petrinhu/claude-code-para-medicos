# Design — Aula 01: O que é o Claude Code

**Data:** 2026-06-08  
**Duração prevista:** ~50-55 min  
**Módulo:** M0 — Primeiros Passos sem Medo (aula 01/05 do módulo)  
**Status anterior:** 🚫 Refatorar — roteiro focava em Windows/Linux como seção principal (não está no HTML); M0.01 não coberto como conceito explícito  
**Formato:** Take único no OBS. Unidirecional.  
**Abordagem pedagógica:** Demo-First — mostrar antes de explicar regras (recomendação do learning-designer)

---

## Objetivo de aprendizagem

Ao final da aula, o aluno:

1. Sabe o que é o Claude Code (M0.01) e entende a diferença com o Claude.ai no navegador
2. Confirma que a instalação funciona e faz a primeira conversa clínica ao vivo (M0.02)
3. Aplica o ciclo pedir / anexar / revisar / iterar com demo ao vivo (M0.03)
4. Conhece as 3 regras de ouro de prompt clínico e pratica o kata ruim→bom (M0.04)
5. Acessa o projeto de qualquer lugar via `/remote` no celular (M0.05)

---

## Analogia central

**CC = prontuário eletrônico do projeto | Web UI = post-it**

- Web UI: responde uma pergunta, fecha, sumiu. Não sabe nada do projeto, não lembra de ontem.
- Claude Code: tem histórico, tem contexto, qualquer especialista pode abrir e continuar de onde parou.

Gancho de abertura: Windows/Linux como "dialeto". Eu uso Linux, aluno usa Windows — terminal é terminal, CC funciona igual nos dois. Frase única, nunca mais volta ao assunto.

## Seção 1 — Âncora + O que é o CC (M0.01) — 10 min

**Abertura (60s):**
> *"Você já ficou até meia-noite reformatando um relatório que podia ter feito em 10 minutos? Ou procurando aquela referência que sumiu do slide? Esta aula é sobre uma ferramenta que vai mudar isso — e não precisa saber nada de computação para usar."*

**Gancho Windows/Linux (30s):**
Dr. Petrus aparece no Linux. Uma frase: "Eu uso Linux, vocês usam Windows — terminal é terminal, CC funciona igual nos dois. Pronto. Assunto encerrado."

**Analogia prontuário/post-it:**
- Apresentar Web UI: "Post-it colado no monitor. Você escreve, ele responde, você fecha. Ele não sabe quem você é, não lembra de ontem, não sabe nada do seu projeto."
- Apresentar Claude Code: "Prontuário eletrônico. Tem histórico, tem contexto, você fecha e abre no dia seguinte — ele sabe exatamente onde estava."
- Mostrar a mesma pergunta clínica nas duas interfaces — mesmo cérebro, contextos diferentes.

## Seção 2 — Primeiro contato ao vivo (M0.02 recap) — 8 min

Confirmação de instalação:
```
claude --version
```
(mostrar versão aparecendo na tela)

Primeira conversa ao vivo:
```
claude
```
Prompt de exemplo: *"Qual a diferença entre FA paroxística e persistente em termos de manejo?"*

Deixar o CC responder na tela enquanto comenta. Depois abrir Web UI (Claude.ai) na mesma pergunta, lado a lado, para o aluno ver:
- mesmo cérebro
- Web UI começa do zero, sem contexto de projeto

---

## Seção 3 — O ciclo de conversa (M0.03) — 12 min

Quatro passos — cada um demonstrado, não só explicado:

**Pedir:** prompt clínico simples, CC responde ao vivo.

**Anexar:** criar arquivo `texto.txt` com trecho de guideline público (não-sensível), passar para o CC:
> *"Resumo este texto em 3 bullets para alunos de medicina."*

**Revisar:** avaliar a resposta com olho clínico. "Está correto? Está no tom certo? Falta alguma coisa?"

**Iterar:** reformular:
> *"Mais conciso. Foco em aplicação clínica no consultório."*

Mostrar antes e depois do mesmo prompt iterado.

Frase-âncora:
> *"Você não troca de colega quando ele entendeu errado. Você reformula o pedido."*

## Seção 4 — Bons hábitos + Kata de prompt (M0.04) — 12 min

### 3 regras de ouro

**Regra 1 — Dê contexto clínico**

Kata ao vivo:
- Prompt ruim: `"Me fala sobre depressão."` → mostrar resultado genérico
- Prompt bom: `"Sou psiquiatra. Preciso de uma aula de 30 min sobre diagnóstico de depressão para residentes de clínica médica. Foco em critérios DSM-5 e quando encaminhar. Linguagem acessível."` → mostrar resultado específico e utilizável

**Regra 2 — Zero dado de paciente (LGPD)**

Contraste ao vivo:
- Errado: `"João da Silva, 45 anos, RG 123456, queixa de..."` — parar, explicar o risco (LGPD, dado identificável, ética médica)
- Correto: `"Paciente masculino, 45 anos, queixa de..."` — mesmo resultado clínico, sem dado pessoal

Frase-âncora: *"Isso vai aparecer em toda aula deste curso. Vou repetir até vocês sonharem."*

**Regra 3 — Seja específico**

Prompt vago = resposta vaga. Lei de qualquer sistema: *garbage in, garbage out.*

## Seção 5 — CC no celular + Fechamento (M0.05) — 8 min

**Demo `/remote`:**

```
/remote
```
Gera link → abrir no celular, no navegador → mostrar projeto acessível de qualquer lugar, contexto preservado.

**Síntese (~90s):**
1. CC = prontuário | Web UI = post-it
2. Ciclo: pedir, anexar, revisar, iterar
3. 3 regras: contexto / zero dado / específico
4. `/remote`: de qualquer lugar, mesmo contexto

**Dever de casa:**
> Escreva 3 prompts sobre situações do seu dia a dia clínico. Para cada um: a versão ruim e a versão melhorada. Não precisa rodar — só escrever. Traga para a aula_02.

**Ponte para aula_02:**
> *"Na próxima aula você usa o Claude Code com arquivos reais: PDF clínico, planilha do consultório, geração de slides. Você já sabe conversar. Na aula_02 você começa a trabalhar."*

## Notas de produção

- **S2 — Web UI lado a lado:** deixar aba do Claude.ai aberta no navegador antes de começar a gravação
- **S4 — Kata de prompt:** rodar o prompt ruim primeiro, deixar o resultado aparecer na tela antes de cortar para o bom — não editar depois
- **S3 — arquivo de demo:** preparar `texto.txt` antes da gravação com trecho de guideline público (AHA/ESC, sem dado de paciente)
- **S5 — `/remote`:** ter celular carregado e na mesma rede Wi-Fi que o computador de gravação
