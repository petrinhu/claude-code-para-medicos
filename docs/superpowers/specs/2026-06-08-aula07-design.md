## Objetivo de aprendizagem

Ao final da aula, o aluno:

1. Gera e analisa um CSV de dados do consultório (faturamento, no-show, sazonalidade) — M3.05 indicadores
2. Identifica padrões financeiros acionáveis: melhor convênio, pior dia de no-show, meses fracos/fortes
3. Cria e reutiliza um prompt-receita mensal — automação honesta sem programação — M3.05 automação
4. Gera um dashboard HTML offline com gráficos, que abre no navegador sem servidor — M3.05 visualização
5. Fecha o M3 pronto para decidir se avança para a fase opcional

---

## Decisões de design

| Decisão | Escolha | Motivo |
|---|---|---|
| Persona do cenário | Metabologista — continuidade do M3 | Aulas 05+06 usam metabologista; coesão narrativa do módulo |
| CSV: tipo de dado | Consulta / Retorno / Procedimento (genérico) | Universal para qualquer especialidade; cirurgia era exclusivo para ~20% |
| Objetivo dominante | Entender os números (faturamento + no-show + sazonalidade) | Mais acessível; margem por convênio exige dados de custo que aluno raramente tem |
| Automação | Prompt-receita reutilizável + checklist de fechamento | Honesto: "automação do pensar, não do clicar"; macros Excel exigem TI |
| Dashboard HTML | Self-contained (Chart.js embutido, sem CDN) | Funciona offline; pré-gerar backup para gravação segura |
| Posição da automação | Seção dedicada (S5) entre análise e dashboard | M3.05 explícito; aluno sai sabendo o que é automação sem programação |
| LGPD | Reforço explícito em S5: des-identificar antes de subir dado real | Essa é a aula onde o risco real é máximo — aluno vai usar dados reais |

**Metabologista de consultório, 3 convênios, problema duplo: não sabe qual convênio paga mais e não sabe em qual dia há mais no-show.**

## Seção 2 — Cenário (4 min)

Persona: mesma metabologista das aulas 05 e 06. Consultório próprio, 3 convênios + particular.

**Problema 1:** não sabe qual convênio paga mais pela mesma consulta. Acha que o Unimed paga melhor, mas não tem certeza — só descobre quando o extrato chega e nem entende o extrato.

**Problema 2:** a taxa de no-show está alta mas não sabe em qual dia da semana. Desconfia que é segunda-feira — e provavelmente está certa — mas sem dado é chute.

> *"Hoje você vai ter os dados. Tudo em uma tela, em um arquivo. Que você manda para o contador e ele entende."*

## Seção 3 — Demo: CSV (8 min)

Gerar planilha simulada com nomes fictícios (LGPD-safe desde o início).

Prompt:
```
Gere uma planilha CSV simulada com 120 atendimentos de um consultório de
endocrinologia/metabolismo dos últimos 6 meses (janeiro a junho de 2025).

Colunas:
- Data: distribuída entre janeiro e junho de 2025
- Dia_semana: segunda a sexta
- Tipo_atendimento: Consulta (primeira vez), Retorno, Procedimento
  (proporções realistas — Retorno é o mais frequente)
- Convenio: Unimed, Bradesco, SulAmérica, Particular
  (distribua de forma realista — Unimed é o mais comum)
- Valor_tabela_R$: valor que o convênio deveria pagar
- Valor_recebido_R$: valor que efetivamente entrou (menor que tabela = glosa)
- Status: Realizado, No-show, Cancelado
- Mes: janeiro a junho (para facilitar agrupamento)

Use "Paciente 001, 002..." se precisar de coluna de paciente.
Salve como consultas_2025.csv.
```

Após a demo: explicar glosa (valor_tabela vs valor_recebido), chamar atenção para a coluna Status. Nota: "Procedimento" na coluna Tipo_atendimento = qualquer procedimento ambulatorial (infiltração, biópsia, eletrocauterização) — não cirurgia. Cirurgião lê como cirurgia, psiquiatra lê como sessão, a lógica financeira é idêntica.

## Seção 4 — Demo: Indicadores (8 min)

Prompt:
```
Analise o arquivo consultas_2025.csv e me entregue um relatório
de indicadores de gestão do consultório:

1. Faturamento total dos 6 meses (valor recebido)
2. Faturamento por convênio — ranking do maior para o menor pagador
3. Taxa de glosa por convênio: diferença entre valor_tabela e valor_recebido
4. Taxa de no-show geral (%) e por dia da semana — em qual dia tenho mais falta?
5. Sazonalidade: os 3 meses com mais atendimentos e os 3 com menos
6. Tendência de faturamento mês a mês — estou crescendo ou caindo?

Para cada indicador: uma tabela + uma frase de interpretação prática.
```

Após a demo: comentar cada indicador com reação clínica. "Segunda realmente lidera no no-show? Confirme e já ajuste a agenda."

## Seção 5 — Demo: Automação (9 min)

**Conceito (2 min):**
> *"Automação sem programação é isso: você escreve o prompt uma vez e usa todo mês. O trabalho que se repete não é o resultado — é o raciocínio. E o Claude guarda o raciocínio para você."*

**Demo — Prompt-receita reutilizável (4 min):**

Rodar o mesmo prompt de indicadores com um segundo CSV (julho simulado):
```
[mesmo prompt de indicadores da seção anterior — rodar com consultas_julho.csv]
```
Revelar: o relatório saiu com a mesma estrutura, sem reescrever nada. *"Isso é a receita. Todo mês você troca o arquivo, não o prompt."*

**Demo — Checklist de fechamento mensal (2 min):**
```
Crie um checklist de fechamento financeiro mensal para um consultório
de metabolismo, em passos numerados, para eu seguir todo último dia útil do mês.
Inclua: conferência de repasses de convênio, glosas a recontestar,
faturamento particular recebido, contas fixas a pagar, e os 3 indicadores
que devo calcular. Formato: lista de tarefas com [ ].
```

**LGPD explícito (1 min):**
> *"Quando você for usar dados reais do seu consultório — e você vai — siga esta regra: des-identifica antes de subir. Nome do paciente vira 'Paciente 001'. CPF: apaga. Diagnóstico nominal: apaga. O Claude precisa do padrão financeiro — data, convênio, valor, status. Não precisa saber quem é o paciente."*
>
> *"Dado que identifica o paciente nunca entra. O padrão financeiro pode entrar des-identificado."*

## Seção 6 — Demo: Dashboard HTML (12 min)

Prompt (self-contained — Chart.js embutido, sem CDN):
```
Com base nos dados de consultas_2025.csv, crie um dashboard de gestão
do consultório de metabolismo.

O resultado deve ser um único arquivo HTML que funciona no navegador
sem precisar de internet ou servidor (self-contained).
A biblioteca de gráficos deve estar EMBUTIDA dentro do próprio arquivo —
sem nenhum link para CDN ou internet externa.

Conteúdo:

Linha superior — 4 cards de resumo:
- Faturamento total (6 meses)
- Total de atendimentos realizados
- Taxa de no-show (%)
- Convênio que mais paga

Gráficos:
1. Barras: faturamento recebido por convênio
2. Linha: faturamento mensal (janeiro a junho)
3. Barras horizontais: no-show por dia da semana

Tabela: sazonalidade — atendimentos por mês (meses fortes/fracos destacados)

Estilo: limpo, fundo branco, cores sóbrias.
Salve como dashboard_consultorio.html.
```

Após a demo:
- Abrir o arquivo no navegador ao vivo
- Abrir no celular (mesma rede, via /remote ou QR)
- **Debrief explícito:** *"Este arquivo tem 500 linhas de código por dentro. Você não viu nenhuma. Você só descreveu o que queria. É exatamente assim que o Claude Code funciona: você descreve o resultado, ele constrói os meios."*

## Seção 7 — Fechamento do M3 (5 min)

**Resumo da aula_07:**
CSV de 6 meses → indicadores → prompt-receita reutilizável → dashboard offline. Sem Excel complexo. Sem Power BI. Sem programar.

**Dever de casa:**
> *"Pegue uma planilha real do seu consultório. Antes de qualquer coisa: des-identifica. Nome → Paciente 001. CPF → apaga. Depois peça ao Claude os mesmos indicadores que a gente gerou hoje. E salve o prompt como receita — você vai usar no mês que vem."*

**Fechamento do M3 — dois destinos válidos (validar quem para ANTES de convidar):**
> *"Você acabou o Módulo 3.*
>
> *Pensa no que você fez:*
> *aula_05: criou conteúdo para o Instagram e newsletter em minutos.*
> *aula_06: montou um estudo científico com análise estatística e pôster.*
> *aula_07: transformou dados do consultório em indicadores e dashboard.*
>
> *Tudo sem programar. Tudo descrevendo o problema em linguagem natural.*
>
> *Se você quiser parar aqui: você já entrega mais do que a maioria dos médicos com IA.*
>
> *Se quiser ir além: a fase avançada começa na próxima aula. Vai ter um pouco de código — mas guiado, passo a passo, do jeito que você aprendeu um novo protocolo. O dashboard que você fez hoje é a versão descartável. Na fase avançada você aprende a construir algo que fica permanente. A habilidade é a mesma que você já tem — só vai mais fundo.*
>
> *Nos dois casos: obrigado por chegar até aqui."*
