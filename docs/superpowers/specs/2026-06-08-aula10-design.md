**Data:** 2026-06-08

**Formato:** Take único no OBS. Unidirecional.  
**SO-alvo:** Windows/PowerShell único (curso assume Windows como plataforma dos alunos)  
**Abordagem pedagógica:** Concreto → Abstrato (Kolb); "por quê" antes do "como" (Knowles); retrieval ativo a cada passo  
**Zero código:** O aluno NUNCA escreve código em nenhuma aula deste curso — essa é a premissa de todo o curso. O Claude escreve, o médico descreve e supervisiona. Nesta aula, a prova de vida usa o `main.py` gerado automaticamente pelo `uv init`, sem edição.

---

## Objetivo de aprendizagem

Ao final da aula, o aluno:

1. Instala o uv e cria o projeto ClinMd-Tribe com `uv init`
2. Lê e interpreta o `pyproject.toml` como "prontuário do projeto"
3. Instala uma dependência com `uv add` e vê o pyproject.toml ser atualizado
4. Entende o que é ambiente virtual (`.venv`) com a analogia do carrinho de medicação
5. Executa o primeiro código do ClinMd-Tribe com `uv run` — sem escrever uma linha de Python

## Seção 3 — uv: por que existe (2 min)

> *"Python tem um ecossistema enorme de bibliotecas — ferramentas prontas que você usa no projeto.*
>
> *O problema: duas bibliotecas às vezes precisam de versões incompatíveis de uma terceira.*
>
> *É como uma interação medicamentosa: remédio A e remédio B funcionam sozinhos. Juntos, conflito.*
>
> *O uv resolve isso. Ele é o gerenciador de dependências — a farmácia do projeto.*
>
> *Ele sabe exatamente quais remédios o projeto precisa, em qual versão, e garante que nada conflita.*
>
> *Primeiro passo: instalar a farmácia."*

## Seção 4 — Demo: install + init (8 min)

Comandos em Windows/PowerShell.

Instalar o uv (winget, método recomendado para Windows):
```
winget install --id=astral-sh.uv -e
```

Alternativa se winget não estiver disponível:
```
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Fechar e reabrir o PowerShell. Confirmar instalação (sinal vital):
```
uv --version
```

Navegar para a pasta de projetos (criada na aula_abertura):
```
cd $HOME\Documents\projetos
```

Criar o projeto:
```
uv init clinmd-tribe
cd clinmd-tribe
dir
```

Mostrar os 3 arquivos criados: `.python-version`, `main.py`, `pyproject.toml`.

> *"Três arquivos. A farmácia está de pé. Ainda vazia — mas organizada."*

## Seção 5 — Demo: type pyproject.toml (5 min)

```
type pyproject.toml
```

Ler e explicar cada campo:

```
[project]
name = "clinmd-tribe"
version = "0.1.0"
description = "Add your description here"
requires-python = ">=3.11"
dependencies = []
```

> *"name: o nome do projeto. version: 0.1.0 — versão inicial, em desenvolvimento.*
>
> *requires-python: precisa de Python 3.11 ou mais novo.*
>
> *dependencies: a lista de remédios. Está vazia. O prontuário existe, mas o paciente ainda não tem prescrição.*
>
> *Nota importante: você não edita esse arquivo na mão. O uv edita por você."*

## Seção 6 — Demo: uv add + .venv + uv.lock (10 min)

O ClinMd-Tribe vai ter interface gráfica. Instalar o Flet:

```
uv add flet
```

Ver o pyproject.toml atualizado:
```
type pyproject.toml
```

> *"Olha: dependencies agora tem 'flet'. O prontuário foi atualizado automaticamente."*

Ver os novos arquivos:
```
dir
```

> *"Apareceram duas coisas novas: a pasta `.venv` e o arquivo `uv.lock`.*
>
> *A pasta `.venv` é o ambiente virtual — e aqui a farmácia fica mais interessante.*
>
> *Imagine que você tem dois projetos: o ClinMd-Tribe e um projeto de pesquisa.*
>
> *O ClinMd-Tribe precisa do Flet versão X. O projeto de pesquisa precisa do Flet versão Y.*
>
> *Se você instalasse tudo no mesmo lugar, haveria conflito — como misturar o carrinho de medicação do leito 3 com o do leito 7.*
>
> *O `.venv` é o carrinho do leito 3. Só tem o que este projeto precisa. Não mistura com ninguém."*

Ver o uv.lock:
```
type uv.lock
```

> *"O uv.lock é o registro da dispensação: remédio X, versão Y, fonte Z.*
>
> *Você não edita esse arquivo nunca. O uv cuida dele.*
>
> *Se você precisar recriar o projeto em outro computador, o uv.lock garante que tudo fica idêntico."*

## Seção 7 — Demo: uv run (8 min)

Ler o que o `uv init` criou automaticamente no main.py — sem editar nada:

```
type main.py
```

> *"O uv init gerou esse arquivo por você. Sem você escrever uma linha.*
>
> *O curso inteiro vai ser assim: você descreve o que quer, o Claude escreve.*
>
> *Você lê, revisa, aprova. Nunca digita código.*
>
> *Agora vamos executar o que o uv criou."*

Executar com uv run:
```
uv run python main.py
```

> *"Funcionou. E perceba: usamos `uv run` — não `python` direto.*
>
> *Por quê? Porque o `uv run` garante que o Python usa o ambiente deste projeto — o carrinho de medicação do leito 3, não o estoque geral do hospital.*
>
> *Regra simples e definitiva: dentro do projeto ClinMd-Tribe, todo comando Python começa com `uv run`. Sempre.*
>
> *O Claude vai fazer isso por você na maioria das vezes. Mas quando você vir `uv run` no terminal, você vai saber exatamente o que está acontecendo."*

## Seção 8 — Referência de comandos uv (5 min)

| Comando | O que faz |
|---|---|
| `uv init nome` | Cria projeto novo |
| `uv add pacote` | Instala dependência |
| `uv remove pacote` | Remove dependência |
| `uv run python arquivo.py` | Executa no ambiente do projeto |
| `uv sync` | Reinstala tudo a partir do pyproject.toml |

> *"`uv sync` é o comando para recriar a farmácia em outro computador. Você clona o projeto, roda `uv sync`, e o uv instala exatamente o que está no pyproject.toml.*
>
> *Uma dica prática: o Claude Code vai usar esses comandos por você. Quando você pedir para adicionar uma calculadora, ele vai rodar `uv add` se precisar de uma dependência nova, vai criar arquivos, vai organizar as pastas.*
>
> *Você não precisa digitar tudo manualmente. Mas precisa entender o que acontece quando o Claude diz que fez.*
>
> *Você assina a evolução, não assina às cegas."*

> type pyproject.toml
