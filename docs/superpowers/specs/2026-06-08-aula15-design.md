## Seção 1 — Abertura: o código embolado (gancho da dor)

Abre com o main.py da calculadora de IMC (aula_13). Pede ao Claude Code:

```
No main.py da calculadora de IMC, muda o critério de obesidade grau 2
para IMC > 35 e adiciona obesidade grau 3 para IMC > 40.
```

O aluno vê que a mudança de diretriz clínica está enterrada junto com código de tela, botão e entrada de dados. Modificar o critério clínico exige navegar por código de interface.

**Analogia:** prontuário onde anamnese, prescrição e conta do hospital estão no mesmo parágrafo. Mude um, borra os outros.

**Frase de virada:** "Arquitetura é a resposta para esse problema. Não é teoria. É o remédio."

## Seção 2 — Ponte da analogia: corpo → plantão

Transição explicitamente narrada:

> "No setup eu dei a foto estática — pele, tecido, músculo, osso — pra você sentir que existem camadas empilhadas. Serviu pra isso. Hoje a gente troca pela versão que SE MEXE, porque arquitetura é sobre fluxo: quem chama quem, quem decide o quê."

**Tabela do plantão (âncora visual):**

| Camada técnica | Plantão | O que faz | Frase-âncora |
|---|---|---|---|
| Apresentação | Recepção / balcão | Recebe o paciente, mostra a tela, coleta dados. Não decide nada clínico. | "Onde o paciente é recebido e as coisas aparecem" |
| Aplicação | Enfermagem de triagem | Orquestra: pega pedido da recepção, aciona quem precisa, organiza a ordem. Não é dona da regra clínica. | "Quem coordena o fluxo, mas não decide a conduta" |
| Domínio | O médico / protocolo clínico | A regra de decisão pura: o escore, o critério diagnóstico. Não sabe se há tela ou banco de dados. | "A regra médica em si — o cálculo, o protocolo" |
| Infraestrutura | Laboratório / arquivo / farmácia | Executa pedidos: guarda no disco, busca no banco, lê PDFs. Não pensa, não decide. | "Onde as coisas são guardadas e buscadas" |

**Regra de ouro da arquitetura:** a dependência aponta para dentro. O Domínio (protocolo clínico) existe independente de ter recepção bonita ou laboratório X ou Y. Você pode trocar o laboratório sem mudar o diagnóstico.

## Seção 3 — As 4 camadas no plantão (fio narrativo único)

Um único caso atravessando as 4 camadas: **calcular o CHA2DS2-VASc**

- **Recepção (Apresentação):** o formulário coleta idade, fibrilação atrial, AVC prévio, HAS, diabetes, ICC. Não calcula nada — só recebe e exibe.
- **Triagem (Aplicação):** pega os dados do formulário, chama o protocolo CHA2DS2-VASc, pede à Infraestrutura para salvar o resultado. Orquestra — não decide a conduta.
- **Médico (Domínio):** o algoritmo puro: idade > 75 = 2 pontos, AVC prévio = 2 pontos, idade 65-74 = 1 ponto, etc. Não sabe se há interface gráfica ou terminal. Só sabe medicina.
- **Laboratório (Infraestrutura):** salva o resultado num arquivo local. Executa o pedido da triagem. Não pensa — só armazena.

**Ponto de retorno ao gancho:** "Agora pense: mudou a diretriz e idade > 75 passa a valer 2 pontos em vez de 1. Onde você mexe? Só no Médico (Domínio). A Recepção não sabe que existiu uma mudança. O Laboratório continua salvando. A Triagem continua orquestrando. Apenas o protocolo clínico mudou."

## Seção 4 — Mapa de arquiteturas

6 abordagens com analogia hospitalar, quando usar e risco principal:

| Arquitetura | Analogia hospitalar | Quando faz sentido | Risco principal |
|---|---|---|---|
| **Monolítico** | Consultório solo: médico faz tudo | Script interno, MVP, ferramenta solo de curta duração | Escala mal; mudar uma coisa quebra outra |
| **3 camadas** (front/mid/back) | Clínica simples: recepção + consultório + farmácia | App médio com separação básica | Regra clínica fica no "meio", difícil de isolar |
| **4 camadas + Foundation** | Hospital completo: balcão + triagem + médico + lab | ClinMd-Tribe | Mais pastas; requer disciplina |
| **Clean Architecture** | Hospital com protocolos padronizados: Domínio ao centro, independente de tudo | Sistemas complexos e testáveis | Curva de aprendizado; abstração exige prática |
| **Hexagonal (Ports & Adapters)** | Hospital com múltiplas entradas intercambiáveis: PS, ambulatório, telemedicina | Quando há múltiplas formas de entrada/saída intercambiáveis | Abstração extra dificulta para iniciantes |
| **Microsserviços** | Rede hospitalar: oncologia + cardiologia + ortopedia comunicando por protocolos | Produto de grande escala, múltiplos times independentes | Over-engineering para o nosso caso; coordenação enormemente complexa |

**O monólito ainda faz sentido hoje?** Sim. Scripts de automação interna, ferramentas de uso próprio, MVPs de validação rápida, projetos solo de curta duração. O problema não é o monólito em si — é usar monólito num projeto que vai crescer.

**Por que Clean Architecture para o ClinMd-Tribe?** Porque o Domínio (os protocolos clínicos) precisa ser isolado, testável e independente de interface. Quando a diretriz muda, só o protocolo muda. Quando o layout muda, o protocolo não sabe.

## Seção 5 — Recuperação ativa

3 perguntas com a tela fechada, antes de abrir para o jogo:

1. "O que faz a triagem (Aplicação)?" → orquestra o fluxo, não decide a conduta
2. "O que o médico (Domínio) sabe fazer?" → só o protocolo clínico — não sabe de tela nem de banco
3. "O laboratório (Infraestrutura) calcula o CHA2DS2-VASc?" → não — só armazena e busca

## Seção 6 — Jogo "Em que camada eu mexo?"

5 features em ordem crescente de ambiguidade. O aluno classifica **antes** de o instrutor confirmar. Debrief obrigatório em cada resposta: "por que essa e não outra?"

| # | Feature | Camada correta | Observação pedagógica |
|---|---------|----------------|----------------------|
| 1 | "Quero o botão Calcular em roxo" | Apresentação | Óbvio — aquece o jogo |
| 2 | "Mudou a diretriz: idade > 75 agora vale 2 pontos" | Domínio | Reencontra a dor do gancho — fecha o arco |
| 3 | "Quero salvar o resultado num arquivo TXT" | Infraestrutura | Consolida o papel do laboratório |
| 4 | "Ao salvar, quero que apareça confirmação na tela" | Aplicação + Apresentação | Propositalmente ambíguo — orquestração + exibição |
| 5 | "Quero adicionar o PHQ-9 ao lado do CHA2DS2-VASc" | Atravessa tudo | Mostra que features grandes tocam o sistema inteiro — e está tudo bem |

**Saída honesta para dúvida:** ensinar que não saber a camada exata é normal. Solução: descreve a feature em linguagem clínica e pergunta ao Claude Code — "em que camada isso mexe e por quê?" O Claude diz, o aluno valida.

## Seção 7 — Mini-demo: prompt ao Claude Code

Prompt exato que o aluno digita:

```
Cria um arquivo chamado arquitetura.txt mostrando a estrutura de pastas
do ClinMd-Tribe com as 4 camadas da Clean Architecture.
Para cada pasta, adiciona um comentário explicando o que vai ali.
Use nomes em inglês com comentários em português.
```

Resultado esperado:

```
clinmd-tribe/
  presentation/     # telas Flet: botões, campos, janelas, AppBar
  application/      # orquestração: lê tela, chama domínio, pede pra salvar
  domain/           # regras clínicas: CHA2DS2-VASc, PHQ-9, critérios diagnósticos
  infrastructure/   # arquivos, banco de dados SQLite, indexação de PDFs
```

Este arquivo (arquitetura.txt) será o mapa de referência nas próximas aulas.
