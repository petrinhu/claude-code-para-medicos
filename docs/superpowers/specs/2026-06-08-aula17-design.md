## Objetivo de aprendizagem

Ao final da aula, o aluno:

1. Descreve o Claude Code como residente — colaborador que executa e erra, não oráculo infalível
2. Explica com analogia clínica o que é um LLM e por que ele pode errar
3. Entende o que o Claude "lembra" dentro de uma sessão e o que esquece entre sessões
4. Escreve um prompt clínico bom (resultado descrito, tipos de dado, sem dado real)
5. Usa `/clear` para limpar o contexto e `/help` para ver capacidades
6. Aplica o padrão de anonimização LGPD em qualquer prompt clínico

## Seção 2 — O que é um LLM (7 min)

**Analogia:** radiologista que leu 100 milhões de laudos. Reconhece padrões com enorme precisão — mas não consulta uma verdade absoluta. Prevê o próximo token mais provável. Por isso "sabe medicina" mas pode inventar uma dose. Não é malícia: é o mecanismo.

Conceitos abordados:
- LLM = Large Language Model — modelo de linguagem treinado em texto
- Diferença entre "saber" e "prever"
- Por que ele é útil mesmo errando às vezes

---

## Seção 3 — Contexto e Memória (6 min)

**Analogia:** memória de trabalho no plantão. O Claude lembra tudo desta sessão como o plantonista lembra o caso que está acompanhando agora. Quando a sessão termina, o plantonista novo começa do zero — só sabe o que está escrito nos arquivos do projeto (CLAUDE.md, os `.py`).

- `/clear` = pedir um plantonista novo no meio do turno (contexto limpo)
- O que persiste entre sessões: os arquivos do projeto
- O que não persiste: a conversa

---

## Seção 4 — Por que o Claude Erra (5 min)

**Analogia:** o colega que "chuta com confiança". Ausência de incerteza explícita — ele não sabe que não sabe.

Regra de ouro: **você é o atestante final**. Nunca assina laudo sem revisar.

Técnica prática: pedir para o Claude revisar a própria resposta antes de aceitar:
```
Revise a resposta anterior. Algum dado clínico pode estar incorreto?
```

---

## Seção 5 — Demo A/B: Prompt Ruim vs Bom (8 min)

Exemplo isolado (fora do ClinMd-Tribe, em sessão nova).

**Prompt ruim:**
```
faz uma calculadora de escore cardíaco
```
Resultado: genérico, critérios inventados, sem especificação.

**Prompt bom:**
```
Cria uma função Python chamada calcular_cha2ds2vasc que recebe 7 parâmetros
booleanos (fibrilacao_atrial, avc_previo, has, diabetes, icc, sexo_feminino)
e um inteiro (idade). Retorna o escore total somando os pontos:
- avc_previo: 2 pontos
- idade > 75: 2 pontos
- idade entre 65 e 74: 1 ponto
- has, diabetes, icc, sexo_feminino: 1 ponto cada
Inclua um exemplo de chamada com valores fictícios.
Sem interface gráfica — só a função.
```
Resultado: preciso, testável, correto.

**O delta visível entre os dois resultados é o professor.**

## Seção 6 — Demo CLI vs Web: Lendo Arquivos (5 min)

No ClinMd-Tribe, Claude Code lê os 4 placeholders de uma vez:
```
Leia os arquivos presentation/tela_inicial.py, application/orquestrador.py,
domain/calculadoras.py e infrastructure/armazenamento.py.
Me diga qual camada ainda não tem nenhuma lógica clínica implementada.
```
Claude responde citando cada arquivo. Isso é impossível no Claude.ai web — diferencial concreto do CLI.

## Seção 7 — LGPD como Skill de Prompt (4 min)

Não é palestra — é técnica transferível.

**Padrão de anonimização:**
```
Paciente fictício: 64 anos, sexo masculino, HAS + fibrilação atrial.
Sem nome real, sem CPF, sem data de nascimento real.
```

Demo lado a lado — mesmo pedido clínico:
- **Errado:** inclui nome, idade exata, CRM do médico
- **Correto:** dado anonimizado, contexto clínico preservado

O aluno sai com um padrão aplicável imediatamente em qualquer prompt.
