# Design — Aula 19: BigTech Virtual — Montando o Time Completo

**Data:** 2026-06-08  
**Duração prevista:** ~38 min  
**Submódulo:** 04 — Agents e BigTech Virtual (aula 03/04)  
**Formato:** Gravado em take único no OBS. Unidirecional.

---

## Objetivo de aprendizagem

Ao final da aula, o aluno:

1. Reconecta o "residente de plantão" (aulas 17-18) com um hospital inteiro de especialistas atrás dele
2. Usa `/bigtech` para convocar o time adequado ao ClinMd-Tribe via Cósimo/Chief of Staff
3. Consulta `@narciso-ciso` sobre proteção de dados clínicos locais
4. Consulta `@caetano-cto` sobre decisão de persistência (SQLite vs JSON)
5. Reconhece que o mesmo problema recebe ênfases distintas de cada especialista
6. Registra a decisão num ADR-001 leve no projeto ClinMd-Tribe

---

## Analogia central

**Hospital terciário com interconsulta.**

Você não pede ao residente parecer definitivo de neurocirurgia. Você convoca o titular do serviço.
`/bigtech` é o pedido de interconsulta multidisciplinar — você descreve o caso, o Cósimo convoca a junta certa.

Mapeamento honesto:

| Realidade técnica | Analogia clínica |
|---|---|
| Claude Code "cru" (aulas 17-18) | Residente generalista — competente, mas não é titular de cada especialidade |
| Agents operacionais (backend, frontend, qa…) | Especialistas de cada serviço |
| C-levels (CTO, CISO, CFO…) | Chefes de serviço / direção clínica |
| Cósimo + `/bigtech` | Regulador / coordenador de interconsultas |
| Dr. Petrus | Diretor do hospital — autoridade final |

Nota de rigor pedagógico (falar na aula): agent = residente com POP de especialidade carregado. Não é uma equipe consciente — é um arquivo de texto com persona especializada. Isso costura aula_18 → aula_19.

## Seção 1 — Reconexão: O Hospital Inteiro (4 min)

Retoma a promessa do fim da aula_18:

> "Na aula passada você equipou seu residente: maleta com skills, MCP como cabo para ferramentas externas, checklist automático com hooks. Mas tudo isso era sobre um só residente. Hoje você conhece o hospital inteiro que existe por trás dele."

Apresentar a analogia do hospital terciário: o residente está no plantão, mas existe um corpo clínico completo disponível para interconsulta — cada um titular de uma especialidade.

---

## Seção 2 — O Organograma (5 min)

Apresentar a constelação como tabela visual. NÃO listar 65 agentes — mostrar apenas os relevantes para o ClinMd-Tribe.

C-levels a nomear (6 principais):
- **Cósimo** — Chief of Staff, regulador, convoca a junta (invocado pelo `/bigtech`)
- **Caetano** — CTO, decisões de stack e arquitetura
- **Narciso** — CISO, segurança e privacidade (LGPD)
- **Cláudio** — CLO, jurídico e compliance
- **Capitolino** — CPO, escopo do produto / o que construir
- **Celso** — CEO, decisões estratégicas

Agents operacionais: existem mais de 50 — `backend-engineer`, `frontend-engineer`, `qa-engineer`, `security-engineer`, `devops-sre`. NÃO listar todos.

**Frase libertadora:** "Você não precisa decorar 65 nomes. Quem decora é o Cósimo."

## Seção 3 — Demo `/bigtech` (8 min)

Entrar na pasta do ClinMd-Tribe:
```
cd Documents\projetos\clinmd-tribe
claude
```

Prompt:
```
/bigtech
```

O Cósimo classifica o porte do ClinMd-Tribe (solo/early), mas **mantém Narciso e Cláudio ativos** apesar do projeto ser pequeno — porque dado de saúde/PII exige CISO e CLO independente de porte.

**Ponto-chave:** mostrar ao aluno por que o CISO e o CLO não foram cortados. Isso reforça o eixo LGPD transversal de todo o curso.

---

## Seção 4 — Demo `@narciso-ciso` (7 min)

Prompt:
```
@narciso-ciso O ClinMd-Tribe vai salvar evoluções clínicas no computador do médico.
Como protejo esses dados?
```

O Narciso responde com foco em:
- Modelo de ameaça local (dado que nunca sai da máquina)
- Criptografia em repouso
- Privacidade por design (LGPD)
- Secrets fora do repositório

---

## Seção 5 — Demo `@caetano-cto` (7 min)

Prompt:
```
@caetano-cto O ClinMd-Tribe precisa guardar dados localmente.
SQLite ou arquivo JSON — qual recomendar?
```

O Caetano responde com foco em:
- Viabilidade de stack (SQLite é trivial com Python)
- Simplicidade vs. overhead
- Custo de manutenção para projeto solo

**Ponto pedagógico:** o aluno vê que a **mesma questão de persistência** recebe ênfases completamente diferentes do Narciso (segurança) e do Caetano (viabilidade). Isso prova que o "chapéu" muda a resposta — agents não são o mesmo Claude com label diferente.

---

## Seção 6 — Artefato: ADR-001 (4 min)

Prompt:
```
Com base nas consultas ao @narciso-ciso e ao @caetano-cto,
cria o arquivo docs/decisoes/ADR-001-persistencia-local.md
resumindo a decisão de persistência do ClinMd-Tribe.
Formato simples: contexto, decisão, justificativa, consequências.
```

Mensagem-chave: "Consultou → registrou." O hábito profissional de registrar a decisão após a interconsulta.

## Seção 7 — Tabela + Encerramento (3 min)

Tabela de bolso "quando chamar quem":

| Tipo de decisão | Especialista |
|---|---|
| Stack, arquitetura, código | `@caetano-cto` |
| Segurança, LGPD, privacidade | `@narciso-ciso` |
| O que construir / escopo / MVP | `@capitolino-cpo` |
| Montar o time para o projeto | `/bigtech` |

**Dever de casa — A junta dos 3 pareceres:**

> Pense em 3 decisões pendentes do ClinMd-Tribe. Para cada uma:
> 1. A decisão, em uma frase
> 2. Qual titular convocar
> 3. O prompt `/bigtech` ou `@especialista` que você usaria
>
> Não execute — só escreva. Traga para a próxima aula.
