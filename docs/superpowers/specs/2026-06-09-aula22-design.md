## Decisão de reestruturação do S05

A aula_22 originalmente concentrava HAS-BLED + PHQ-9 + GAD-7. Após brainstorming com learning-designer e engineering-coach, ficou decidido:

- **S05.02 / aula_22 = HAS-BLED** (solo — fecha o arco FA da aula_21)
- **S05.03 / aula_23 = PHQ-9 + GAD-7** (novo paradigma Likert 0-3; os dois juntos pois estrutura idêntica)
- **S05.04 / aula_24 = HAM-D, YMRS, AUDIT, CAGE** (mantido)
- **S05.05 / aula_25 = MMSE, MoCA, PANSS, CGI, CURB-65, MELD, SOFA** (slot novo)
- Aulas S06 em diante sobem +1 (aula_25→aula_26, etc.)
- **Total do curso: 53 aulas** (era 52)

Razão pedagógica: HAS-BLED é booleano/cardio (mesmo padrão da aula_21, deliberate practice). PHQ-9/GAD-7 introduzem paradigma novo (Likert 0-3) — misturar os dois em uma aula fragmenta a retenção.

## Objetivo de aprendizagem

Ao final da aula, o aluno:

1. Entende o HAS-BLED como complemento obrigatório do CHA₂DS₂-VASc na decisão de anticoagulação em FA
2. Escreve um prompt descritivo mais curto e mais seguro do que na aula_21 — aplicando o padrão já aprendido com menos andaime
3. Valida o app com os dois scores na tela e vê a decisão clínica completa ao vivo
4. Reconhece o limite da calculadora: quando ambos os scores são altos, a ferramenta estrutura o raciocínio — não decide

## Decisões de design

| Decisão | Escolha | Motivo |
|---|---|---|
| Persona | Cardiologista (mesmo da aula_21) | Continuidade narrativa — mesmo paciente, decisão incompleta |
| Paciente âncora | 68M, HAS controlada, DM, FA | Reusa o caso da aula_21 — aluno já conhece o gabarito CHA₂DS₂-VASc=3 |
| Duração | ~45 min (vs. 55 da aula_21) | Aluno já conhece o padrão — menos andaime, mais velocidade |
| HAS-BLED | Versão simplificada 7 critérios (A e D como booleanos, max=7) | Mais limpo de implementar e explicar; clinicamente equivalente para o nível do curso |
| Cutoff HAS-BLED | <3 = baixo; 3 = moderado; >3 = alto | Padrão clínico consolidado |
| Climax UI | Painel de Decisão FA embutido na tela HAS-BLED | Mostra os dois scores juntos sem tela extra — impacto máximo |
| Leitura supervisionada | 3 perguntas (vs. 5 na aula_21) | Aluno já sabe onde olhar — deliberate practice sem andaime excessivo |
| Validação cruzada | 2 casos (vs. 3 na aula_21) | Duração reduzida; o caso 2 é o ponto pedagógico mais denso |

## Referência clínica — HAS-BLED (versão simplificada)

| Letra | Critério | Pontos |
|---|---|---|
| H | Hipertensão não controlada (PAS >160 mmHg) | 1 |
| A | Disfunção renal OU hepática | 1 |
| S | AVC/AIT prévio | 1 |
| B | Sangramento prévio ou predisposição | 1 |
| L | INR lábil (tempo em faixa terapêutica <60%) | 1 |
| E | Idade > 65 anos | 1 |
| D | Drogas antiagregantes/AINE OU álcool | 1 |

**Score máximo:** 7  
**Interpretação:** <3 = baixo risco · 3 = risco moderado · >3 = alto risco de sangramento

**Caso-âncora (68M, HAS controlada, DM):**
H0 + A0 + S0 + B0 + L0 + E1 + D0 = **1 → Baixo risco de sangramento**

**Decisão FA completa:**
CHA₂DS₂-VASc=3 (Anticoagular) + HAS-BLED=1 (baixo risco) → **Anticoagular — baixo risco de sangramento**

## Gabaritos de validação

| Caso | Perfil | HAS-BLED | CHA₂DS₂-VASc | Decisão |
|---|---|---|---|---|
| 1 (âncora) | 68M, HAS controlada, DM | E=1 → **1** | 3 | Anticoagular — baixo risco |
| 2 (contraste) | 78F, HAS descontrolada + DRC + AVC prévio + sangramento GI + INR lábil + AAS | H+A+S+B+L+E+D → **7** | 6 | Decisão individualizada — discutir risco/benefício |

O caso 2 é o ponto pedagógico central: quando ambos os scores são altos, a calculadora não decide — estrutura o raciocínio para a conversa com o paciente. Frase-âncora: *"A ferramenta não é oráculo. É andaime."*

## Prompt descritivo (a ser digitado ao vivo na aula)

```
Implemente a calculadora HAS-BLED no ClinMd-Tribe
respeitando a Clean Architecture das 4 camadas:

domain/calculadoras/hasbled.py
  - Classe HasBled com 7 campos booleanos:
    has_descontrolada, disfuncao_renal_hepatica, avc_previo,
    sangramento_previo, inr_labial, idoso, drogas_alcool
  - Método calcular() → score inteiro 0-7
  - Método interpretar(score) → str
    - score < 3 → "Baixo risco de sangramento"
    - score == 3 → "Risco moderado de sangramento"
    - score > 3 → "Alto risco de sangramento"

application/servicos/calculadora_service.py
  - Adicionar função calcular_hasbled(dados: dict) → dict
    Retorna: {"score": int, "interpretacao": str}

presentation/telas/calculadora_hasbled.py
  - Tela Flet com:
    - 7 checkboxes para os critérios HAS-BLED
    - Botão "Calcular HAS-BLED"
    - Exibir score em destaque
    - Exibir interpretação: verde (<3) / amarelo (=3) / vermelho (>3)
    - Seção "Decisão FA":
      - Campo numérico: "CHA₂DS₂-VASc (da calculadora anterior)"
      - Campo radio: sexo do paciente (Masculino / Feminino)
      - Exibir recomendação combinada:
        · CHA₂DS₂-VASc ≥ cutoff E HAS-BLED < 3 →
          "Anticoagular — baixo risco de sangramento" (verde)
        · CHA₂DS₂-VASc ≥ cutoff E HAS-BLED ≥ 3 →
          "Decisão individualizada — discutir risco/benefício" (laranja)
        · CHA₂DS₂-VASc < cutoff →
          "Sem indicação de anticoagulação" (cinza)
      (cutoff: ♂ ≥2 · ♀ ≥3, conforme aula_21)
```

## Seção 2 — HAS-BLED como especificação (7 min)

> *"Você já tem um lado da balança: CHA₂DS₂-VASc=3, anticoagular indicado. Mas anticoagular tem um custo. Hoje você calcula o outro lado."*

Percurso:
1. Mostrar os 7 critérios com pontuação
2. Destacar o L (INR lábil) — critério mais frequentemente esquecido
3. Mostrar cutoff: <3 baixo, 3 moderado, >3 alto
4. Calcular o caso âncora à mão: **E=1 → score 1 → baixo risco**
5. Salvar esse resultado: *"O gabarito é 1. O app vai ter que bater esse número."*

---

## Seção 3 — O prompt descritivo (7 min)

Frase pedagógica: *"Na aula_21 você precisou de mim para escrever o prompt. Hoje você vai perceber que ficou mais fácil — porque você já sabe o padrão."*

O professor digita mais rápido, comenta menos cada linha. A aceleração é proposital: é evidência de que o aluno está internalizando o método.

---

## Seção 5 — Leitura supervisionada (8 min)

Roteiro de 3 perguntas:

1. *"O campo `inr_labial` está no domínio? É o critério mais esquecido."* → checar `domain/`
2. *"O método `interpretar()` está usando ≥3 para risco moderado, não ≥2?"* → verificar cutoff
3. *"A seção Decisão FA está chamando o serviço de cálculo, não fazendo o cálculo direto na tela?"* → checar `presentation/`

Frase-âncora: *"Você não lê para entender Python. Você lê para assinar o laudo."*

---

## Seção 6 — Climax: os dois scores na tela (8 min)

Fluxo:
1. `uv run python main.py` → abrir a tela HAS-BLED
2. Preencher o caso âncora: apenas E=1 (68 anos), restante desmarcado
3. Calcular → score 1 → "Baixo risco de sangramento"
4. Na seção Decisão FA: inserir CHA₂DS₂-VASc=3, masculino
5. Resultado: **"Anticoagular — baixo risco de sangramento"** (verde)
6. Frase: *"Os dois lados da balança. A decisão virou dado."*

---

## Seção 7 — Validação cruzada (4 min)

| Caso | Perfil | HAS-BLED | CHA₂DS₂-VASc | Painel mostra |
|---|---|---|---|---|
| 2 | 78F, HAS descontrolada, DRC, AVC prévio, sangramento GI, INR lábil, AAS | 7 | 6 | "Decisão individualizada — discutir risco/benefício" (laranja) |

Ensino: *"A calculadora não decide por você quando os dois scores são altos. Ela estrutura a conversa com o paciente. Isso não é limitação — é honestidade clínica."*
