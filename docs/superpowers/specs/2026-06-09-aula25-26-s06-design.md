## Decisões de design

| Decisão | Escolha | Motivo |
|---|---|---|
| Persona | Ortopedista com alto volume de glosas | Múltiplos convênios, glosas em materiais e honorários, KPIs dramaticamente motivadores |
| Arco narrativo | Linear progressivo: dados (S06.01) antes de gráficos (S06.02) | Dado real motiva; S06.02 recupera o que S06.01 salvou (retrieval practice) |
| Persistência | SQLite via sqlite3 stdlib | Analogia prontuário eletrônico, prepara S07 RAG, SELECT é quase português |
| Campos | 3 + chave: mes + ano + receita_bruta + glosas + n_consultas | Mínimo suficiente para os 3 KPIs; menos para supervisionar |
| Caminho do banco | Path(__file__).parent.parent / "data" / "clinmd.db" | Absoluto relativo ao código — não quebra ao rodar de outra pasta |
| Schema | CREATE TABLE IF NOT EXISTS | Idempotente, auto-explicativo, sem migrations desnecessárias |
| KPIs | receita_liquida + taxa_glosa + ticket_medio | Cobrem as três perspectivas: volume, eficiência, produtividade |
| Guard divisão por zero | if receita_bruta > 0 / if n_consultas > 0 | Mês de férias ou mês novo não quebra o app |
| Gráficos | BarChart (receita líquida) + LineChart (taxa de glosa) | Barra para valor discreto por mês; linha para tendência |
| Alerta visual | taxa_glosa > 15% -> card vermelho | Limiar clínico-financeiro relevante para ortopedista |
| .gitignore | data/*.db nunca commitado | Dado financeiro sensível, reforço LGPD |
| 2 aulas separadas | S06.01: CRUD + persistência / S06.02: KPIs + gráficos | Dois "primeiros contatos" pesados — não condensar |

## Fio narrativo

**O app que esquece vs o app que lembra.**

Ortopedista. Consultório próprio. Agosto foi pesado: glosas do plano X subiram de novo. Ele quer saber se é tendência ou mês isolado. As calculadoras do S05 não respondem — calculavam e esqueciam. O dashboard responde — mas só se o app lembrar os meses anteriores.

S06.01 constrói a memória: o ortopedista cadastra 6 meses, fecha o app, reabre, os dados ainda estão lá. Momento "aha" de persistência.

S06.02 lê a curva: os mesmos dados viram gráfico. Agosto sobe em vermelho na linha de taxa de glosa. A tendência estava lá — esperando para ser vista.

**Fio condutor pedagógico:** *"As calculadoras do S05 eram um médico com amnésia anterógrada — calculava e esquecia. O dashboard do S06 é o prontuário: o dado de hoje ainda está lá amanhã."*

**Bridge S07:** *"O ClinMd-Tribe agora tem memória financeira. Na próxima aula: memória clínica. RAG — o app que aprende com seus próprios documentos."*

## Modelo de dados

```python
# domain/financeiro/registro_mensal.py
class RegistroMensal:
    mes: int          # 1-12
    ano: int          # ex: 2025
    receita_bruta: float
    glosas: float
    n_consultas: int

    def calcular_kpis(self) -> dict:
        receita_liquida = self.receita_bruta - self.glosas
        taxa_glosa = self.glosas / self.receita_bruta if self.receita_bruta > 0 else 0.0
        ticket_medio = receita_liquida / self.n_consultas if self.n_consultas > 0 else 0.0
        return {
            "receita_liquida": receita_liquida,
            "taxa_glosa": taxa_glosa,
            "ticket_medio": ticket_medio,
        }
```
