## Objetivo de aprendizagem

Ao final do módulo S07, o aluno:

1. Entende o que é RAG e por que "embedding = significado virou número"
2. Usa o PubMed MCP (já aprendido na aula_03) para baixar artigos reais e construir um `knowledge_base/`
3. Implementa um indexador idempotente com ChromaDB + sentence-transformers, 100% local
4. Implementa busca semântica que cita a fonte e admite quando não sabe
5. Integra o RAG na tela Flet do ClinMd-Tribe e sabe diagnosticar busca de má qualidade

---

## Decisões de design

| Decisão | Escolha | Motivo |
|---|---|---|
| Stack RAG | ChromaDB + sentence-transformers (`all-MiniLM-L6-v2`) | Melhor qualidade em PT-BR médico; roda em CPU sem GPU; 100% local |
| Formato knowledge_base | `.txt` (texto extraído via PubMed MCP) | Elimina pypdf e problema de PDF escaneado; mais robusto para o aluno |
| Download dos artigos | Ao vivo com Claude Code + PubMed MCP durante aula_28 | Fecha o arco da aula_03; demonstra o loop completo MCP → knowledge_base |
| Idempotência | IDs determinísticos: `nome_arquivo + "_" + numero_trecho` | Rodar o indexador 2x não duplica trechos |
| Chunking | Por parágrafo com overlap de 1 parágrafo | Nunca corta frase clínica no meio |
| Arquitetura | Clean Architecture 4 camadas; `import chromadb` SOMENTE em `infrastructure/` | Regra de dependência da aula_15; mudança de banco vetorial = 1 arquivo |
| .gitignore | `knowledge_base/` e `data/chroma_db/` não commitados | Dados e índice são do ambiente local, não do repositório |
| Persona | Cardiologista | Continuidade com S05; knowledge_base = artigos de anticoagulação em FA — sinônimos densos que fazem busca semântica brilhar |
| S07.04 escopo | Integração Flet + diagnóstico de qualidade da busca | A integração é rápida (aluno já fez 6 telas); a qualidade da busca é o que realmente frustra em RAG real |

## 3 riscos técnicos → perguntas de leitura supervisionada

| Risco | Problema | Pergunta de supervisão |
|---|---|---|
| A — Caminho relativo | `PersistentClient(path="data/chroma_db")` quebra fora da pasta raiz; indexa em pasta errada silenciosamente | *"O caminho do `chroma_db` está ancorado na raiz do projeto — igual ao `clinmd.db`?"* |
| B — Re-indexação duplicada | `collection.add()` sem verificação de ID existente duplica trechos se o indexador roda 2x | *"Se você rodar o indexador duas vezes, o número de trechos dobra ou permanece igual?"* |
| C — Chunking que corta frase | Corte em N caracteres fixos separa "dose máxima é" de "500mg/dia" em chunks diferentes | *"Abra um trecho no terminal — ele termina com uma ideia completa ou está cortado no meio?"* |

## Arquitetura — arquivos criados no S07

```
knowledge_base/                          ← artigos .txt baixados via PubMed MCP
                                           (NÃO commitado: adicionar ao .gitignore)
data/chroma_db/                          ← banco vetorial ChromaDB persistido
                                           (NÃO commitado: adicionar ao .gitignore)

domain/rag/
  resultado_busca.py                     → entidade pura: ResultadoBusca(trecho, fonte, numero_trecho, score)
  porta_busca.py                         → interface abstrata BuscaRAG.buscar(consulta, n) → list[ResultadoBusca]
                                           ZERO import chromadb aqui

infrastructure/rag/
  txt_loader.py                          → lê .txt de knowledge_base/ (caminho ancorado)
                                           chunking por parágrafo + overlap de 1 parágrafo
                                           metadado: nome_arquivo + numero_trecho
  chroma_repositorio.py                  → ÚNICO arquivo que importa chromadb
                                           PersistentClient(path = raiz / "data" / "chroma_db")
                                           indexar() idempotente via IDs determinísticos
                                           implementa interface BuscaRAG

application/servicos/
  indexador_service.py                   → orquestra txt_loader + chroma_repositorio
                                           imprime: "X trechos indexados de Y arquivos"
  busca_service.py                       → recebe pergunta, chama porta_busca
                                           lista vazia se não encontrar — nunca texto inventado

presentation/telas/
  tela_busca_rag.py                      → campo de pergunta, botão Buscar
                                           lista de resultados COM fonte visível (nome do .txt)
                                           chama busca_service — nunca toca em chromadb
```

## Prompt descritivo — Indexador (aula_28, Parte 2)

```
Implemente o indexador do ClinMd-Tribe respeitando Clean Architecture (4 camadas).
Lê arquivos .txt de knowledge_base/ e indexa no banco vetorial em data/chroma_db/.

infrastructure/rag/txt_loader.py
  - Lê todos os .txt de knowledge_base/
    (caminho ancorado na raiz: Path(__file__).parent.parent / "knowledge_base")
  - Chunking por parágrafo com overlap de 1 parágrafo entre trechos consecutivos
  - Cada trecho guarda metadado: nome_arquivo (str) e numero_trecho (int)
  - Retorna lista de dicts com: {"texto": str, "nome_arquivo": str, "numero_trecho": int}

infrastructure/rag/chroma_repositorio.py
  - chromadb.PersistentClient com path ANCORADO na raiz do projeto:
    Path(__file__).parent.parent / "data" / "chroma_db"
  - Usa get_or_create_collection("clinmd_rag")
  - Método indexar(documentos: list[dict]) → None
    IDs determinísticos: f"{doc['nome_arquivo']}_{doc['numero_trecho']}"
    Usa upsert (não add) para garantir idempotência

application/servicos/indexador_service.py
  - Importa txt_loader e chroma_repositorio
  - Chama o loader, manda indexar
  - Imprime no terminal: "X trechos indexados de Y arquivos"

NÃO importe chromadb em application/ nem em domain/. Apenas em infrastructure/.
Ao final, me diga como rodar o indexador pelo terminal.
```

## Prompt descritivo — Buscador (aula_29)

```
Implemente a busca semântica do ClinMd-Tribe sobre data/chroma_db/.
Respeite as 4 camadas.

domain/rag/resultado_busca.py
  - Entidade pura ResultadoBusca com campos:
    trecho: str, fonte: str, numero_trecho: int, score: float

domain/rag/porta_busca.py
  - Interface abstrata BuscaRAG com método:
    buscar(consulta: str, n: int) → list[ResultadoBusca]
  - ZERO import de chromadb aqui — só o contrato

infrastructure/rag/chroma_repositorio.py
  - Atualizar arquivo existente: implementar a interface BuscaRAG
  - Usar o mesmo PersistentClient já criado no indexador
  - Retornar os N trechos mais próximos semanticamente
  - SEMPRE incluir fonte e numero_trecho nos resultados

application/servicos/busca_service.py
  - Recebe a pergunta do médico (str) e n (int, padrão 3)
  - Chama BuscaRAG.buscar()
  - Se lista vazia: retorna lista vazia — nunca texto inventado
  - Retorna list[ResultadoBusca]

Regras:
  - Nenhum dado sai da máquina. Busca 100% offline.
  - Todo resultado DEVE ter fonte. Trecho sem fonte não pode ser exibido ao médico.

Me mostre como testar a busca pelo terminal antes de conectar na tela.
```

## Diagnósticos de qualidade da busca — aula_30

| Sintoma | Causa | Como diagnosticar |
|---|---|---|
| Trechos sem sentido / muito curtos | Chunk pequeno demais | Ver tamanho dos trechos em `txt_loader.py` |
| "0 trechos indexados" para um arquivo | `.txt` vazio (abstract indisponível no PMC) | Abrir o arquivo — está vazio? Buscar outro artigo |
| Resultados repetidos 2x | Indexação rodou 2x sem idempotência | IDs duplicados no ChromaDB |
